# 시장 데이터 실행기: 10분 단위 작업 계획

> 2026-11-20 기준. 대상은 [로드맵의 다음 작업](04_todo_roadmap.md#가장-먼저-할-5개-작업)인 거래일·시장·종목 반복, 실패 기록·재시도·증분 수집이다. 각 묶음은 **개별 작업 시간 목표가 10분 이내**이며, 외부 API 응답·대량 백필 완료 시간까지 보장한다는 뜻은 아니다. 한 묶음의 검증이 끝나면 그 결과를 보고 다음 묶음으로 넘어간다.

## 현재 출발점

- [`fetch_market_data.py`](../pipeline/fetch_market_data.py): 한 거래일·한 시장의 가격/외국인 보유량 적재. 종목을 지정해 필터링할 수 있다.
- [`fetch_investor_trading.py`](../pipeline/fetch_investor_trading.py): 한 종목·기간의 투자자 매매 적재.
- [`smoke_market_data.py`](../pipeline/smoke_market_data.py): 지정 날짜·종목 표본을 두 번 적재하고 DB 값을 비교한다.
- [`pipeline/krx/runner.py`](../pipeline/krx/runner.py): R1의 실행 계획 CLI와 dry-run을 구현했다. 기존 `pipeline.runner` 명령도 같은 CLI로 연결된다. [2종목·5거래일 실데이터 검증](07_ingestion_run_2026-11-20.md)은 완료했다.

### 코드 트리

수집원과 역할을 기준으로 묶는다. R1에서 KRX 계획 코드를 먼저 옮겼고, 기존 수집기 경로는 사용 중인 명령·테스트가 깨지지 않도록 유지한다.

```text
pipeline/
├── krx/
│   ├── plan.py              R1: 입력 검증·날짜 후보 생성, 외부 I/O 없음
│   └── runner.py            R1: CLI·dry-run; R2 이후 실행 경로 확장
├── runner.py                기존 실행 경로의 호환 진입점
├── fetch_market_data.py     기존 KRX 가격·보유량 수집기
├── fetch_investor_trading.py 기존 KRX 투자자 거래 수집기
├── smoke_market_data.py     기존 소규모 적재 검증
└── fetch_data.py            기존 ECOS 수집기
```

R2 이후 KRX 수집기를 `pipeline/krx/`로 이동할 때 기존 모듈은 얇은 호환 진입점으로 남기고 호출부·테스트·문서를 함께 갱신한다. ECOS 수집기는 별도 `pipeline/ecos/`로 정리한다. 이동 자체만을 위해 전체 코드를 한 번에 바꾸지는 않는다.

## 작업 순서

```text
R1  [완료] 실행 범위 정의·dry-run
 └─ R2  거래일 확인·작은 범위 실행
     └─ R3  DB 상태 기반 증분·재실행
         └─ R4  제한된 재시도·실패 기록
             └─ R5  수집량·결측 검증과 결과 요약
                 └─ R6  여러 시장/종목으로 확대
```

| 묶음 | 이번 묶음에서 구현할 것 | 완료 기준과 검증 |
| --- | --- | --- |
| **R1 — 완료** | `pipeline/krx/plan.py`와 `runner.py`에 시장, 시작일·종료일, 명시적 6자리 종목 목록을 받는 CLI와 실행 계획 출력(`--dry-run`) 추가. 날짜 역전·중복 종목·잘못된 시장은 실행 전에 거부 | 외부 API·DB 쓰기 없이 계획을 출력하고 입력 오류 테스트 통과 |
| **R2 — 다음 작업** | R1의 범위를 실제 호출에 연결. 요청 날짜가 거래일인지 KRX 응답/캘린더로 확인하고 휴장일은 명시적으로 건너뜀. 처음에는 **한 시장·2종목·최대 5거래일**만 실행 | 기존 표본 명령과 같은 날짜·종목의 가격·보유량·매매 행을 조회하고 누락된 거래일을 보고 |
| R3 | 날짜·종목별 DB 상태를 조회해 이미 완전하게 적재된 단위는 건너뛰고, 불완전한 단위는 다시 수집. UPSERT를 사용해 재실행 가능하게 유지 | 같은 명령을 두 번 실행해 두 번째에 불필요한 API 호출이 없고 행 수가 증가하지 않음 |
| R4 | KRX 요청의 일시적 실패에 횟수·간격이 제한된 재시도 적용. 최종 실패는 날짜·시장·종목·단계와 함께 기록하고 실패 종료 코드 반환 | 모의 일시 오류에서는 재시도 후 성공하고 지속 오류에서는 실패 단위를 확인할 수 있음 |
| R5 | 거래일별 가격·보유량 행 수, 투자자 거래의 `FOREIGN` 존재, 핵심 필드 결측, 매수−매도=순매수를 검증하고 성공·건너뜀·실패 수를 요약 | 누락/불일치 모의 사례가 실패로 분류되고 실제 작은 표본의 요약이 DB 조회 결과와 일치 |
| R6 | 검증된 실행기를 전체 KOSPI, 이후 KOSDAQ/KONEX로 확대. 요청 속도와 처리 구간을 조절하고 장기간 백필은 별도 배치로 분할 | 날짜별 최신일·행 수를 기록하고 중단 후 해당 구간부터 다시 실행 가능 |

## 범위와 운영 원칙

- **R1은 dry-run으로, R2–R5는 작은 실데이터 표본으로 검증한다.** 전체 시장·장기간 백필은 R6에서 별도로 실행한다. 수집 범위가 커지면 10분 제한 때문에 날짜·종목 묶음별로 끊는다.
- 휴장일을 데이터가 없는 실패와 구분한다. KRX가 비어 있는 응답을 반환했다고 임의로 거래일을 건너뛰지 않는다.
- 가격/보유량은 날짜·시장 스냅샷, 투자자 거래는 종목·기간 호출이라는 현재 API 단위를 유지한다. 같은 스냅샷을 종목마다 반복 요청하지 않는다.
- 인증값은 `.env`에서만 읽고 출력하지 않는다. 실패 기록에는 예외 종류와 작업 식별자만 남긴다.
- `smoke_market_data.py`는 변경 전후의 회귀 확인에 계속 사용한다. `runner.py`는 운영용 증분 실행 경로로 발전시킨다.

## R1 사용 예

```bash
python -m pipeline.runner --market KOSPI --start 20261113 --end 20261119 --tickers 005930 000660 --dry-run
```

출력 날짜는 **달력 날짜 후보**다. 주말·휴장일이 포함될 수 있으며 R2에서 실제 거래일을 확인한다. R1은 인증 정보나 DB 연결 없이 실행된다. `--dry-run` 없이 실행하면 쓰기 작업을 시작하지 않고 오류로 종료한다.

**다음에 시작할 작업은 R2다.**
