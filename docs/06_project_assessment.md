# 프로젝트 분석과 실행 계획

> 기준: 2026-11-20 저장소 코드·문서·노트북. Python 구문은 확인했다. 로컬에 의존성이 없어 KRX/ECOS API 호출과 DB 적재는 실행 검증하지 않았다. 아래에서 “구현”은 코드가 있다는 뜻이며, 운영 데이터가 쌓였다는 뜻은 아니다.

## 1. 프로젝트의 목적과 현재 위치

한국 주식시장에서 외국인 순매수·보유비중 변화가 이후 종목 수익률과 변동성에 어떤 관계가 있는지 검증한다. 환율·금리·시장/업종 흐름 등 공통 요인을 고려해 유효한 조건을 찾고, 검증 결과로 종목별 기회 신호와 위험 알림을 제공하려 한다. 매매 지시보다 데이터 기준일, 예측 기간, 근거와 불확실성을 보여 주는 의사결정 지원 도구를 지향한다. 자세한 가설은 [제품 비전](01_product_vision.md)에 있다.

```text
ECOS 거시지표 ────────┐
KRX 가격·시총 ────────┤
KRX 외국인 보유량 ────┼─> PostgreSQL raw ─> [staging] ─> [mart/피처] ─> [신호·백테스트] ─> [서비스]
KRX 투자자별 매매 ────┘                    미구현       미구현            미구현             미구현
노트북의 DART·추가 거시 실험 ─> 정식 파이프라인으로 옮겨야 함
```

## 2. 저장소 구조

```text
plankton/
├── README.md                    프로젝트 소개
├── .env.example                 DB·ECOS·KRX·DART 환경변수 이름
├── docker-compose.yml           로컬 PostgreSQL 16
├── requirements.txt             실행·탐색 의존성의 허용 버전 범위
├── config/settings.py           .env 읽기, DB 설정과 필수 환경변수 조회
├── db/
│   ├── connection.py            DB 연결·트랜잭션 관리
│   ├── models.py                ECOS 4종의 dataclass·행 파서
│   ├── init_schema.sql          raw 스키마·ECOS 4개 테이블
│   ├── migrate.py               초기 스키마·번호별 SQL 적용 이력
│   └── migrations/001_*.sql     종목·가격·투자자 거래·외국인 보유량 테이블
├── pipeline/
│   ├── fetch_data.py            ECOS 환율·외환보유액
│   ├── fetch_market_data.py     KRX 일별 시장 가격·보유량·종목 마스터
│   ├── fetch_investor_trading.py KRX 종목별 투자자 매매
│   └── runner.py                비어 있음
├── test/
│   ├── Analysis.ipynb           삼성전자·거시지표 탐색
│   └── test_fetch_data.ipynb    ECOS·DART 수집 실험
└── docs/                        비전, 데이터 설계, 로드맵, 실행 문서
```

시장 수집은 거래일·시장별, 투자자 거래는 종목·기간별로 직접 호출한다. 전체 시장을 순회하는 실행기는 없다. 명령과 준비 절차는 [KRX 수집 문서](05_market_data_ingestion.md)에 있다. KRX 수집 코드는 계정 환경변수의 **존재만** 검사한다. 실제 인증과 응답 성공은 검증하지 않았다.

### 데이터별 상태

| 데이터 | 저장 위치 | 현재 실행 경로 | 남은 범위 |
| --- | --- | --- | --- |
| 환율 | `raw.krw_exchange_rates` | ECOS 직접 실행 | 분석 대상 통화 선택, 공개 시점·증분 수집 |
| 외환보유액 | `raw.fx_reserves` | ECOS 직접 실행 | 발표일·수정치 관리 |
| 기준금리·국고채 | `raw.bok_base_rates`, `raw.ktb_yields` | 테이블·모델만 있음 | 수집 경로 연결 |
| 종목 기준정보 | `raw.security_master` | KRX 옵션 실행 | 업종·상장 상태·변경 이력 |
| 가격·거래량·시총 | `raw.stock_prices_daily` | KRX 지정일·시장 실행 | 거래일 반복·백필·품질 검증 |
| 외국인 보유량 | `raw.foreign_ownership_daily` | KRX 지정일·시장 실행 | 가격 데이터와 커버리지 비교 |
| 투자자별 거래 | `raw.investor_trading_daily` | KRX 지정 종목·기간 실행 | 유형 충돌 해결, 전체 유니버스 적재 |
| CPI·M2·경기선행·뉴스심리·DART | 정식 테이블 없음 | 노트북 실험 | 스키마·수집기·공개일/기업코드 매핑 |

## 3. 확인된 위험과 검증할 가정

### 데이터 정확성

1. **투자자 유형 충돌:** `fetch_investor_trading.py`는 원본 `외국인`과 `외국인합계`를 모두 `FOREIGN`으로 바꾼다. DB 기본키는 `(date, ticker, investor_type)`이다. 같은 응답에 두 열이 함께 있으면 중복 키나 값 덮어쓰기가 생길 수 있다. 원본 응답과 두 유형의 의미를 확인한 뒤 저장 키를 분리하거나 집계 기준을 정해야 한다.
2. **결측과 0 혼합:** 투자자 거래의 `_integer()`와 `_frame_value()`는 NA 및 누락 날짜·열을 0으로 바꾼다. 실제 거래 0과 응답 누락을 구분할 수 없다. 필수 열·일자 일치와 결측 처리 규칙이 필요하다.
3. **종목 마스터 이력 부족:** `raw.security_master`는 티커당 한 행이고 동기화가 기존 행을 갱신한다. 과거 업종·이름·상장 상태를 재현하기 어렵다. 상장폐지 종목까지 포함하는 시점별 기준정보가 필요하다.
4. **시점 정렬 미구현:** 가격·수급의 장 마감 시점과 거시·재무 데이터의 실제 공개일·수정 이력이 분석 데이터에 반영되지 않는다. 이 상태로 만든 예측 성과에는 미래 정보가 섞일 수 있다.
5. **실패의 가시성:** ECOS 수집기는 구간별 예외를 출력하고 계속 진행한다. 일부 실패해도 완료 메시지가 나오므로 실패 구간 기록·재시도·종료 상태가 필요하다.

### 재현성과 운영

- `config/settings.py`와 `db/connection.py`에 DB 설정 읽기가 중복되고 ECOS 수집기는 별도 연결 코드를 사용한다. `db/models.py`도 현재 수집 경로에서 사용하지 않는다.
- `requirements.txt`는 버전 범위만 지정한다. `.env.example`에는 공백과 인라인 주석이 섞여 있어 복사 후 설정 값을 명확히 채우기 어렵다.
- 수집 일정, 백필·증분 구분, API 재시도, 행 수·최신일·결측률 점검, 자동 테스트가 없다. `test/`는 탐색 노트북 보관용이다.
- 현재 노트북 소스에서는 ECOS 키를 환경변수로 읽는다. 기존 문서의 과거 키 노출 주장은 Git 이력을 조사해 확인해야 한다. 노출이 확인되면 키를 폐기·재발급하고 노출 경로를 정리한다. `.env`는 현재 `.gitignore`에 있다.

## 4. 다음 작업 트리

```text
P0  데이터 정확성과 실행 기반
├─ 1. KRX 원본 응답 표본 확인 → 투자자 유형 정의와 중복 키 수정
├─ 2. 결측/0, 날짜·종목·시장별 행 수 검증 규칙
├─ 3. 작은 유니버스 백필과 재실행 검증
├─ 4. 실행기: 거래일·시장·종목 반복, 실패 기록·재시도·증분 수집
└─ 5. 설정/DB 연결 통합, 자동 검증, README·예제 환경변수 정리

P1  분석 가능한 이력
├─ 6. 종목의 시점별 이력·상장폐지·업종·액면분할 처리
├─ 7. 기준금리·국고채 및 필요한 거시지표 정식 수집
├─ 8. 거시/재무 공개일·수정치와 가격/수급의 사용 가능 시점 저장
└─ 9. staging·mart 및 출처·갱신 시각·품질 지표

P2  가설 검증
├─ 10. 외국인 순매수/거래대금 비율, 보유비중 변화 등 피처
├─ 11. 이후 1·5·20·60 거래일 초과수익률·변동성 레이블
├─ 12. 시장·업종·시총·환율 통제와 종목군별 비교
└─ 13. 시계열 표본 외 검증과 거래비용 반영

P3  제품화
├─ 14. 설명 가능한 기회·위험 신호와 백테스트
└─ 15. 종목/시장 화면, 알림, 신호 근거·기준일 표시
```

### 단계별 완료 기준

| 작업 | 산출물 | 완료 판단 |
| --- | --- | --- |
| 1–2 | 원본 열 정의·파서 수정·작은 응답 사례 검증 | 날짜·종목·투자자 유형 키가 유일하고 결측을 0으로 오인하지 않음 |
| 3–4 | 제한된 종목군 백필·일일 실행기 | 지정 기간을 반복 적재해도 결과가 같고 실패 구간을 재처리할 수 있음 |
| 5 | 설정·테스트·실행 문서 | 새 환경에서 DB 초기화와 소규모 수집을 재현하고 최신일·행 수를 확인할 수 있음 |
| 6–9 | 시점별 기준정보·분석 테이블 | 과거 날짜에 공개된 데이터와 당시 상장 종목만 조회할 수 있음 |
| 10–13 | 재현 가능한 분석 코드·결과표 | 시장/업종 기준 초과수익, 위험, 거래비용 후 성과를 표본 외 기간까지 보고함 |
| 14–15 | 신호·화면·알림 | 신호마다 근거, 기준일, 예상 기간, 실패 조건과 과거 성과를 표시함 |

처음 구현할 묶음은 **1–5번**이다. 데이터 의미와 재실행 가능성을 확보해야 이후 분석 결과를 신뢰할 수 있다.
